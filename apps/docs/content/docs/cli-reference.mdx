# CLI Reference

The commands, flags, keys, environment variables and exit codes of muxa.

## Synopsis

```bash
muxa <command> [<command> ...]
muxa -c <command> [name] [-c ...]
muxa -s <package> <script> [name] [-s ...]
muxa -w <package> <command> [name] [-w ...]
muxa workspaces
muxa logs <process> [-f]
```

`muxa` with no arguments prints the help.

## Argument Modes

<Callout type="warning">
  muxa supports two modes that cannot be mixed in a single command. A flag after a basic command
  stops with `Cannot mix basic and advanced arguments`, and an extra argument after a flag's parts
  stops with `Unexpected argument`.
</Callout>

### Basic Mode

Each argument is one command, with no flags and no tab names:

```bash
muxa 'npm run dev' 'npm run test' 'npm run lint:watch'
```

### Advanced Mode

Each process is a flag (`-c`, `-s` or `-w`) and the arguments that belong to it. Unlike in most CLIs, a flag takes several arguments, separated by spaces:

```bash
muxa -s backend dev api -w mobile 'npx expo start' expo -c 'docker-compose up' db
```

| Flag | Package   | Script or command     | Tab name (optional) |
| ---- | --------- | --------------------- | ------------------- |
| `-s` | `backend` | `dev`                 | `api`               |
| `-w` | `mobile`  | `'npx expo start'`    | `expo`              |
| `-c` |           | `'docker-compose up'` | `db`                |

## Options

### `-c, --command <command> [name]`

Run any command in the folder you run muxa from.

```bash
# Without name
muxa -c 'npm run dev'

# With name
muxa -c 'npm run dev' frontend
```

### `-s, --script <package> <script> [name]`

Run a `package.json` script of a workspace package. The package `.` is the folder you run muxa from.

```bash
# Run 'dev' script from 'backend' package
muxa -s backend dev

# Run 'dev' script from the package.json in the folder you run muxa from
muxa -s . dev

# With custom name
muxa -s backend dev api-server
```

muxa runs the script with the [detected package manager](/configuration#package-manager-detection), so `pre` and `post` scripts run where that manager runs them: npm, pnpm and Bun do, Yarn 2 and later does not.

`-s` takes no script arguments. Use `-w` for a script with arguments:

```bash
muxa -w frontend 'npm run build --ignore-scripts'
```

### `-w, --workspace <package> <command> [name]`

Run any command in the folder of a workspace package.

```bash
# Run 'npx vite' in the folder of the 'frontend' package
muxa -w frontend 'npx vite'

# With name
muxa -w frontend 'npx vite' dev-server
```

### `-h, --help`

Display help information. Only as the first argument.

### `-V, --version`

Display the version number. Only as the first argument.

### `workspaces`, `ws`

List the packages muxa finds in the folder you run it from, with that folder itself as `.`.

```bash
muxa workspaces
```

Output example:

```text
Found 4 workspaces (using npm workspaces):
  myapp             .
  @myapp/frontend   apps/frontend
  @myapp/backend    packages/backend
  @myapp/shared     packages/shared
```

With no `package.json` in the folder, it prints `No workspaces found in current directory`.

### `logs <process>`

Print the output of a process, from the last [start line](/usage#log-files) to the end. It reads the log files of the folder you run it from, so it also works after muxa quit.

```bash
muxa logs web

# A process with no name, by its command
muxa logs 'npm run dev'

# Each new line as well, until Ctrl-C
muxa logs web -f

# Plain text through a pipe
muxa logs web | grep -i warning
```

- `<process>` is the name as you typed it, the name in the process list, or the command of a process with no name.
- In a terminal, the output keeps its colors. Anywhere else it is plain text. The log file and the screen of muxa keep every code.
- A line that rewrites itself, such as a progress bar, shows only its last state.
- With `-f` or `--follow`, before or after the process, it prints on as the process writes, until `Ctrl+C`. It goes on when muxa quits and starts again, and when a log file [rotates](/configuration#log-size-limits). A line shows when it ends; a line without an end, such as a question, shows after 2 seconds with no new output.
- A process that the last start did not run prints the output of its own last run.
- When the program that reads the output of `muxa logs -f` stops reading, such as a pager, muxa waits for it. Lines that rotate away twice meanwhile are lost.
- When muxa emptied the log to keep the files under their [size limits](/configuration#log-size-limits), and nothing new is in it, `muxa logs` says so on stderr and exits with 0, or waits for new output with `-f`.
- When two processes have one name, `muxa logs` stops with an error. The second one also answers to the name with the number that the process list shows: `muxa logs 'web (2)'`.
- It works in a process that muxa runs, so an agent started with `muxa -c 'npm run dev' web -c claude agent` can read `web`. A process from `-s` or `-w` runs in its package's folder: go to the folder of the muxa command first.

## Reserved Words

muxa does not run these first words as commands: `workspaces`, `ws`, `check`, `migrate`, `logs`, `restart`, `stop`, `start`.

To run a program with one of these names, use `-c`:

```bash
muxa -c restart
```

## Package Resolution

`-s` and `-w` take a package by any of these:

- **Name** in its `package.json`

  ```bash
  muxa -s @myapp/backend dev
  ```

- **Relative path**

  ```bash
  muxa -s packages/backend dev
  muxa -s ./packages/backend dev
  ```

- **Folder name**, when only one package has it

  ```bash
  muxa -s backend dev
  ```

When one package's name is another package's folder name, muxa takes the folder name.

If several packages have the folder name, muxa shows them all:

```text
Error: Ambiguous package identifier 'backend'
Found multiple matches:
  - @myapp/backend (packages/backend)
  - @tools/backend (tools/backend)
Please use the full package name or path.
```

Which packages muxa finds: [Monorepo Support](/configuration#monorepo-support).

## Tab Names

A process without a name in the command gets one:

| Mode   | Example                           | Tab name      |
| ------ | --------------------------------- | ------------- |
| Basic  | `muxa 'npm run dev'`              | `npm run dev` |
| `-c`   | `muxa -c 'npm run dev'`           | `npm run dev` |
| `-s`   | `muxa -s @myapp/backend dev`      | `backend:dev` |
| `-s .` | `muxa -s . build`                 | `.:build`     |
| `-w`   | `muxa -w mobile 'npx expo start'` | `mobile`      |

`-s` and `-w` use the package's folder name, however the command names the package.

- A name cannot start with `-`.
- A name over 200 characters shows in full, and its [log file](/usage#log-files) takes its first 200 characters.
- When two processes have one name, given in the command or taken from a package, muxa asks `Continue with duplicate names? (y/N)`. `y` starts them with that name; `n` or Enter stops muxa.
- When different names would give one [log file](/usage#log-files), muxa adds a short suffix to the log file of all but one of them: `.web` beside `web` writes `web-oyv.log`, and the process list still shows `.web`. Such names differ only in characters that become `_` (`a b`, `a/b`), in dots at the ends (`.web`, `web`), in a `.log` ending (`web.log`, `web`), or, on macOS, in case (`Web`, `web`). The suffix comes from the name, so it is the same at each start. The name that equals its file name (`web`, in `web.log`) keeps it, or else the first one.

## Shell Wrapping

dekit runs a command without a shell. muxa runs a command through `sh -c` when it contains:

- Shell operators and redirections: `&`, `|`, `;`, `>`, `<`
- Glob patterns: `*`, `?`, `[`, `]`
- Text in braces: `{a,b}`
- Variables: `$VAR`, `${VAR}`
- Subshells and command substitution: `(...)`, `$(...)`, `` `...` ``
- A `~` at the start of a word or after `:`
- A backslash or a quote
- A variable set before the command: `NODE_ENV=production npm run build`
- A `#` at the start of a word, or a line break
- A shell keyword or builtin as its first word: `if`, `cd`, `exit`, `export`

Commands from `-s` and `-w` follow the same rules; they run in the package folder.

```bash
# Run through sh -c
muxa -c 'npm run build && npm test'
muxa -c 'echo $USER'
muxa -c 'NODE_ENV=production npm run build'

# Run without a shell
muxa -c 'npm run dev'
muxa -s backend dev
```

## Environment Variables

Every process inherits the environment muxa runs in, `NODE_ENV` included. Set a variable for one process inside its command:

```bash
# For one process
muxa -c 'NODE_ENV=production npm run build' build

# For every process
DEBUG=app:* muxa -c 'npm run dev' app
```

| Variable         | Set by | Effect                                                                                                                   |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------------------------------ |
| `FORCE_COLOR`    | muxa   | `1` for every process, so tools keep their colors. A value you set is kept.                                              |
| `MUXA_RUNNING`   | muxa   | `1` for every process. muxa starts no process when it is set, so a script that muxa runs cannot start muxa.              |
| `MUXA_DEBUG`     | you    | Any value: muxa prints what it detected and the dekit command, with `[muxa debug]` in front.                             |
| `MUXA_TEST_MODE` | you    | `true`, and no other value: muxa prints the dekit command and some environment variables, and starts nothing. A dry run. |

## Process Management

### Start

- All processes start at once. muxa has no start order; to start one later, wait inside its command: `muxa -c 'sleep 2 && npm start'`.
- A process that fails does not stop the others.
- Each process gets its own pseudo-terminal, so colors, prompts, QR codes and single-key shortcuts work.

### Keys

The keys act on the process list until you focus the output. While the output has focus, every key except `Ctrl+A` goes to the process.

| Key                                        | Effect                                                        |
| ------------------------------------------ | ------------------------------------------------------------- |
| `j`, `k`, `Down`, `Up`, or a click         | Select a process; a click on its output focuses the output    |
| `Ctrl+A`                                   | Switch between the process list and the output                |
| `Ctrl+C`                                   | Send `Ctrl+C` to the selected process                         |
| `s` `x` `r`                                | Start, stop, restart the selected process                     |
| `Page Up`, `Page Down`, `Ctrl+U`, `Ctrl+D` | Scroll the output; the mouse wheel scrolls it too             |
| `z`                                        | Show only the output; `Ctrl+A` goes back                      |
| `v`                                        | Copy mode: move, `v` again to start the selection, `c` copies |
| `p`                                        | All commands                                                  |
| `q`, then `x`                              | Quit: stop every process and exit                             |
| `Q`                                        | Quit at once, without the menu                                |

The quit menu also offers `Save and quit` and `Detach`. Both stop every process, because muxa ends with the screen.

### Exit of a Process

A process that exits shows `DOWN` and its exit code in the process list. Its output stays readable, the other processes keep running, and muxa stays open when every process is down.

### Signals

On `SIGINT`, `SIGTERM` or `SIGHUP` (a closed terminal), muxa stops every process and exits.

## Exit Codes

- `0`: You quit muxa, even when a process failed, or a signal stopped it. Also `--help`, `--version`, `logs`, and `workspaces`, even when it finds none.
- `1`: muxa stopped before it started any process: a bad argument, an unknown package or script, a Settings error, a bad tab name, a rejected duplicate name, muxa inside muxa, no terminal (`Stdin is not a tty`), or no dekit binary for the platform. Also `logs` with no log file for the process, `restart`, `stop`, `start`, `migrate` and `check`.
- `130`: `Ctrl+C` stopped `logs -f`.

## Errors

muxa prints every error and question before dekit takes over the terminal. A package or a script that does not exist gets the list of those that do, and a missing script also the line of `scripts` in the `package.json`:

```text
Error: Package 'fronted' not found in workspace
Available packages: @myapp/backend, @myapp/frontend, @myapp/shared, myapp
```

```text
Error: Script 'test' not found in @myapp/backend (/path/to/packages/backend/package.json:8)
Available scripts: build, dev, lint
```

```bash

```

## Limitations

- In basic mode, an option after the first argument (`muxa 'npm run dev' --help`) and an unknown option with one dash (`-x`) run as commands.
- When input ends with no answer to the duplicate-name question, muxa starts nothing and exits 0.
- `muxa migrate` and `muxa check` only print `Migration tool not yet implemented` ([issue #37](https://github.com/dendotai/muxa/issues/37)).
- `muxa restart`, `muxa stop` and `muxa start` only print `muxa restart is not yet implemented`, and the same for each ([issue #19](https://github.com/dendotai/muxa/issues/19)).
