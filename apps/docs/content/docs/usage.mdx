# Usage Examples

Explore different ways to use muxa for your development workflow.

## Basic Commands

### Running Multiple Commands

The simplest usage - run multiple commands in parallel:

```bash
# Basic mode
muxa 'npm run dev' 'npm run test:watch'

# Advanced mode with flags
muxa -c 'npm run dev' -c 'npm run test:watch'

# With custom tab names
muxa -c 'npm run dev' app -c 'npm run test:watch' tests
```

### Mixed Commands

You can mix different types of commands:

```bash
# Development server + database + file watcher
muxa -c 'npm run dev' app \
     -c 'docker-compose up postgres' db \
     -c 'npm run watch:css' styles
```

## Workspace Script Support

Run package.json scripts from specific workspace packages without complex shell syntax.

### Basic Workspace Usage

```bash
# Run 'dev' script in 'backend' package
muxa -s backend dev

# Run multiple workspace scripts
muxa -s backend dev -s frontend start

# With custom names
muxa -s backend dev api -s frontend start web
```

### Package Managers

One muxa command runs the script with the [package manager your project uses](/configuration#package-manager-detection):

<Tabs items={["npm", "Yarn", "pnpm", "Bun"]}>

    ```bash

    ```

  </Tab>
  <Tab value="Yarn">

    ```bash
    # yarn.lock
    muxa -s frontend dev   # yarn run dev
    ```

  </Tab>
  <Tab value="pnpm">

    ```bash
    # pnpm-lock.yaml
    muxa -s frontend dev   # pnpm run dev
    ```

  </Tab>
  <Tab value="Bun">

    ```bash
    # bun.lockb
    muxa -s frontend dev   # bun run dev
    ```

  </Tab>

To run a process with another package manager, write it out: `muxa -w frontend 'yarn dev'`.

## Run Commands in Workspace Directories

Execute arbitrary commands in workspace directories:

```bash
# Run command in workspace directory
muxa -w backend 'npm run dev' backend-dev
muxa -w mobile 'npx expo start' expo

# Useful for tools not in package.json scripts
muxa -w frontend 'npx vite' vite \
     -w backend 'npx nodemon index.js' api
```

## Complex Commands

### Shell Operators

Commands with shell operators are automatically wrapped:

```bash
# Sequential execution
muxa -c 'npm run build && npm test' build-test

# Conditional execution
muxa -c 'npm test || echo "Tests failed"' tests

# Pipes and redirection
muxa -c 'npm run dev | tee dev.log' dev
```

### Environment Variables

```bash
muxa -c 'PORT=3000 npm run dev' api \
     -c 'PORT=3001 npm run dev' web
```

## Log Files

muxa writes the output of every process to a file in `.muxa/logs/`, beside the `package.json` of the folder you run it from. A process that is not selected, and the lines that scrolled off the screen, are in its file too:

```bash
muxa -s backend dev api -s frontend start web

# In another terminal
muxa logs web
grep -i warning .muxa/logs/*.log
```

[`muxa logs`](/cli-reference#logs-process) prints the output of one process since the last start, also after muxa quit. `muxa logs web -f` prints each new line too.

A file is named after the [tab name](/cli-reference#tab-names) of its process. Every character outside `A-Z`, `a-z`, `0-9`, `-`, `_` and `.` becomes `_`: `backend:dev` writes `.muxa/logs/backend_dev.log`. Different names that would give one file get a [suffix](/cli-reference#tab-names): `.web` beside `web` writes `web-oyv.log`. `processes.json`, in the same folder, holds the name and the file of each process, those of the last start first. A process of an earlier start stays in it until its file is gone, or a later process takes its name or its file.

At each start, muxa adds a line with the local date, time, and time zone to the file of each process it starts:

```text
=== muxa started 2026-01-31 09:30:00+01:00 ===
```

The lines after the last start line belong to the current run, and those above it to earlier runs. muxa keeps the output of earlier runs until the files reach their [size limits](/configuration#log-size-limits).

`.muxa/.gitignore` keeps the folder out of git; your own `.gitignore` stays as it is.

In a folder with no `package.json`, the files go to `~/.local/state/muxa/logs/<folder path>/` (or `$XDG_STATE_HOME/muxa/logs/<folder path>/`), where each `/` of the folder path is `_` and each `_` is `__`. A run in `/Users/me/Downloads` writes to `~/.local/state/muxa/logs/Users_me_Downloads/`.

When muxa cannot write the files, it asks whether to continue without them. With no terminal on its input, it prints a warning and starts.

### A Second muxa in One Folder

Every muxa in one folder shows one set of processes. A second muxa there opens the screen on the processes that already run, and starts the names they lack: `muxa web api` beside a running `web` starts `api`, and the screen shows both. When a name already runs a different command, muxa asks first:

```text
web already runs "bun dev" in this folder. Replace it with "bun start"? (y/N):
```

`y` restarts `web` with the new command. `n` or <kbd>Enter</kbd> exits, and the processes run on. With no terminal on its input, muxa answers No and exits 1.

A quit that stops the processes, from any screen in the folder, stops all of them.

### Restart, Stop, and Start From Another Terminal

From another terminal in the same folder, or from an agent that muxa runs, act on a process of the running muxa:

```bash
muxa restart web
muxa stop web
muxa start web
```

Each does what <kbd>r</kbd>, <kbd>x</kbd> or <kbd>s</kbd> does on the screen of muxa, also after Detach. An agent such as Claude Code runs these like any shell command, so its permission prompt asks before each one. See [`restart <process>`](/cli-reference#restart-process-stop-process-start-process) for the names it takes and its errors.

### Logs for Agents

An agent such as Claude Code reads a process's output with `muxa logs <process>` or from `.muxa/logs/`. When neither `CLAUDE.md` nor `AGENTS.md` beside the `package.json` mentions `muxa logs`, muxa asks once at start:

```text
Add a line about `muxa logs` to CLAUDE.md? (y/N):
```

`y` adds this line to the end of `CLAUDE.md`, and makes the file when there is none:

```text
For a process's output under muxa, run `muxa logs <process>`.
```

`n` or <kbd>Enter</kbd> leaves `CLAUDE.md` as it is, and muxa stores the answer in `.muxa/claude-md-line-declined` and does not ask again. Delete that file to be asked again. With no terminal on its input, or in a folder with no `package.json`, muxa does not ask.

## Real-World Examples

### Full-Stack Development

```bash
# Frontend, backend, and database
muxa -s apps/web dev frontend \
     -s apps/api dev backend \
     -c 'docker-compose up redis postgres' services
```

### Microservices

```bash
# Multiple services with different tools
muxa -s services/auth start auth \
     -s services/users start users \
     -s services/orders start orders \
     -c 'docker-compose up kafka' kafka
```

### Build Pipeline

```bash
# Build multiple packages in parallel
muxa -s shared build shared \
     -s backend build backend \
     -s frontend build frontend
```

### Testing Workflow

```bash
# Run different test suites
muxa -s backend test:unit backend-unit \
     -s frontend test:unit frontend-unit \
     -c 'npm run test:e2e' e2e
```

### Development with Live Reload

```bash
# Development servers with file watchers
muxa -s frontend dev web \
     -s backend dev:watch api \
     -c 'npm run generate:types -- --watch' types
```

## Advanced Patterns

### Development and Production

```bash
# Development mode
muxa -c 'npm run dev:db && npm run dev:api' backend \
     -c 'npm run dev:web' frontend

# Production mode
muxa -c 'npm run start:api' backend \
     -c 'npm run start:web' frontend
```

### Dynamic Port Assignment

```bash
# Use different ports for multiple instances
muxa -c 'PORT=3000 npm run dev' api-1 \
     -c 'PORT=3001 npm run dev' api-2 \
     -c 'PORT=3002 npm run dev' api-3
```

## Tips and Tricks

- **Tab names**: Name a process when its [default tab name](/cli-reference#tab-names) does not say enough. A short lowercase name with dashes (`web`, `api-v2`) is easy to type in `muxa logs`, and its [log file](#log-files) has the same name; muxa accepts any other name too
- **Workspace Detection**: Run `muxa workspaces` to see all detected packages
- **Quotes**: Put a command in single quotes, so your shell passes it to muxa unchanged
